# Технический SEO-аудит

## Когда применять
Клиент или менеджер просит проверить сайт на технические проблемы, либо
перед стартом работ / пресейлом нужна быстрая техническая картина.

## Что нужно на входе
- Домен или стартовый URL (обязательно).
- Опционально: лимит страниц (по умолчанию 100), цели проекта из
  `projects/<client>/config.json` — чтобы понимать приоритетные разделы.

## Шаги

1. **Запусти краулер.** Из папки скилла:
   ```bash
   python scripts/run_audit.py <URL> --max-pages 100 --out result
   ```
   Тяжёлую работу (краулинг, парсинг HTML) делает Python — НЕ парси страницы
   сам, не трать на это дорогую модель.

2. **Прочитай `result/audit.json`.** Структура: `summary` (сводка + разбивка
   проблем по частоте) и `pages` (по записи на страницу со списком `issues`).

3. **Приоритизируй проблемы по влиянию на трафик**, а не по частоте. Логика:
   - **Критично:** страницы с `status_code >= 400`, `noindex` на важных
     страницах, отсутствие H1/title на коммерческих страницах, цепочки
     редиректов.
   - **Важно:** дубли title/description, отсутствие canonical на
     пагинации/фильтрах, медленные ответы (>1500 мс) на ключевых страницах.
   - **Желательно:** alt у картинок, короткий текст на второстепенных
     страницах.
   Если в `config.json` заданы приоритетные разделы — проблемы на них
   поднимай выше.

4. **Сформируй отчёт** в `result/audit-report.md`:
   - Сводка: сколько страниц, сколько с проблемами, топ-5 проблем.
   - Таблица критичных находок: URL → проблема → оценка влияния → что делать.
   - Короткий приоритизированный план (что чинить в первую очередь).
   Пиши по-русски, конкретно, без воды. Для каждой рекомендации — почему это
   влияет на трафик, а не просто «так принято».

## Что НЕ делать
- Не выдумывай данные, которых нет в `audit.json`. Если страница недоступна —
  так и пиши.
- Не дублируй сырой JSON в отчёт — он для приоритизации, а не для копипасты.
- Не превышай `--max-pages` без причины: большие сайты краулим частями.

## Расширение
Скрипт намеренно не лезет в платные API. Когда понадобится — добавь в
`scripts/` отдельные модули (PageSpeed Insights, GSC) и опиши новые шаги
здесь же. Скилл — живой документ.
