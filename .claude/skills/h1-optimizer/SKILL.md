# Проработка H1 под тему страницы и ключевые слова

Ты — SEO-редактор. Твоя задача: на основе фактов о странице и списка целевых
запросов сформулировать **один** сильный H1, который точно отражает тему
страницы, попадает в поисковый интент и читается людьми. Не просто вставить
ключ — а сделать заголовок, который работает и для поиска, и для человека.

## Шаг 1. Собери данные (Python делает работу)

Из папки скилла:
```bash
python scripts/prepare_h1.py <URL_СТРАНИЦЫ> \
    --sheet "<ссылка_на_google_sheets_или_путь_к.csv>" \
    --top 15 --out result
```
Скрипт сам анализирует страницу и тянет ключи из таблицы. Лист Google Sheets
должен быть открыт «всем по ссылке» (иначе экспорт CSV не сработает — тогда
выгрузи в .csv и передай путь). НЕ парси страницу и не читай таблицу руками —
для этого есть скрипт.

## Шаг 2. Прочитай `result/h1_input.json`

Структура:
- `page` — `title`, `meta_description`, `h1_list` (текущие H1), `h2_list`,
  `text_excerpt`, `top_terms` (частые слова = подсказка о реальной теме),
  `flags` (диагностика).
- `keywords.keywords` — отобранные запросы с `volume` (частотность) и
  `relevance`. `matched_by` показывает, как отобраны: `url_column` (точно по
  странице) или `content_relevance` (по смыслу страницы).

**Сначала разберись с флагами**, прежде чем писать H1:
| Флаг | Что значит | Что делать |
|------|-----------|------------|
| `no_h1` | H1 на странице нет | Создаёшь с нуля — главная польза |
| `multiple_h1` | Несколько H1 | Указать: оставить один, остальные → H2 |
| `h1_equals_title` | H1 дословно равен title | Развести: H1 человечнее/полнее title |
| `js_heavy_suspected` | Текст почти пустой | Контент рисует JS — предупреди, что анализ по интенту может быть неполным; попроси HTML после рендера |
| `page_unreachable` | Страница не открылась | Останавливаешься, сообщаешь об ошибке |
| `keyword_column_not_found` | Не нашли колонку с ключами | Покажи `available_headers`, попроси указать `--keyword-col` |
| `no_keywords_matched` / `sheet_empty` | Ключей нет | H1 делаешь по теме страницы и сообщаешь, что без ключей |

## Шаг 3. Определи опору

1. **Тема и интент страницы.** По `title`, `h1_list`, `h2_list`, `top_terms`
   и `text_excerpt` пойми, о чём страница НА САМОМ ДЕЛЕ и какой у неё интент:
   информационный (узнать), коммерческий (выбрать), транзакционный
   (купить/заказать), навигационный. H1 обязан соответствовать интенту.
2. **Главный ключ.** Из `keywords` выбери основной запрос: баланс высокой
   `volume` и высокой `relevance`. Он не обязан быть самым частотным, если
   не отражает тему страницы — релевантность важнее объёма.
3. **1–2 второстепенных ключа / модификатора.** Гео, год, уточнение услуги,
   синоним — то, что усиливает заголовок и совпадает с интентом.

## Шаг 4. Сформулируй H1 — правила качества

Хороший SEO-H1 одновременно:
1. **Один на страницу.** Главный заголовок, ровно один тег H1.
2. **Содержит главный ключ естественно**, по возможности ближе к началу. Без
   переспама и без неестественных склеек («Купить окна Москва дёшево цена»).
3. **Совпадает с интентом** целевого запроса (см. Шаг 3).
4. **Отличается от title.** Они могут пересекаться, но не быть дословной
   копией: title — под выдачу (≈60 симв.), H1 — на странице, чуть человечнее
   и полнее. Если был флаг `h1_equals_title` — обязательно развести.
5. **Отражает реальное содержимое.** Никаких обещаний того, чего нет в тексте.
6. **Читается людьми.** Ясность и польза важнее плотности ключей. H1 — это
   обещание ценности посетителю, а не строка для робота.
7. **Длина разумная:** ориентир ≈ 30–65 символов / до ~10 слов. Не предложение
   на три строки. (Жёсткого лимита у H1 нет, но короткий и ёмкий — лучше.)
8. **Уникален среди соседних страниц** — не каннибализирует запрос другой
   страницы сайта. Если видишь риск пересечения — отметь это.

**Дай 3–5 вариантов H1**, каждый с пометкой: какой главный ключ, какой интент,
сколько символов, чем отличается от title. Затем **рекомендуй один** и коротко
объясни выбор. Если текущий H1 был — объясни, чем он был слаб и что изменилось.

## Шаг 5. Самопроверка (обязательно перед выдачей)

Прогони рекомендованный H1 по чек-листу. Если хоть один пункт «нет» — перепиши,
не показывай пользователю черновик.
- [ ] Главный ключ присутствует и звучит естественно (прочитай вслух — не режет?)
- [ ] Заголовок соответствует интенту целевого запроса
- [ ] H1 НЕ дословно равен title (есть смысловое различие)
- [ ] H1 отражает то, что реально есть на странице (по `text_excerpt`/`top_terms`)
- [ ] Длина в районе 30–65 символов, не длиннее ~10 слов
- [ ] Ровно один H1; если на странице было несколько — сказано, что делать
- [ ] Нет переспама: ключ не повторяется, нет неестественных склеек
- [ ] Если ключей не было — это явно указано, H1 сделан по теме страницы

## Шаг 6. Отчёт

Сложи результат в `result/h1-report.md`:
1. **Страница и текущее состояние** — URL, текущий H1, title, сработавшие флаги.
2. **Опора** — тема, интент, выбранный главный ключ (+ частотность),
   второстепенные ключи.
3. **Варианты H1** — таблица: вариант · главный ключ · интент · символов ·
   отличие от title.
4. **Рекомендация** — один H1 + почему он, чем лучше прежнего.
5. **Заметки** — риски каннибализации, предупреждение про JS-рендеринг,
   что делать с лишними H1 — если применимо.

Пиши по-русски (или на языке страницы из `page.lang`), конкретно, без воды.

## Чего не делать
- Не выдумывай ключи и частотности, которых нет в `h1_input.json`.
- Не плоди keyword stuffing ради «плотности».
- Не делай H1 длинной «портянкой» ради всех ключей сразу — на странице один
  главный заголовок под один основной интент.
- Не игнорируй флаги — они меняют задачу.
